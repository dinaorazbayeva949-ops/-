# Система поздравления юбиляров

Автоматически находит сотрудников с юбилеем (50, 55, 60, 65 лет и т.д.) и
рассылает им персональное поздравление по email — по расписанию, без
ручных действий.

Как это работает:
1. Вы храните **один общий файл** `data/employees.xlsx` в репозитории.
2. Каждый день GitHub Actions запускает скрипт, который сверяет сегодняшнюю
   дату со списком и находит тех, у кого сегодня юбилей.
3. Для каждого юбиляра формируется письмо (с учётом пола — «Уважаемый» /
   «Уважаемая» определяется по окончанию ФИО) и отправляется через SMTP.
4. Отправленные поздравления фиксируются в `data/sent_log.csv`, чтобы никто
   не получил письмо дважды.

## Структура репозитория

```
birthday-jubilee-system/
├── data/
│   ├── employees_template.xlsx   ← шаблон, замените на свой файл
│   └── sent_log.csv              ← создаётся автоматически, не трогать
├── scripts/
│   └── send_congrats.py          ← основная логика
├── .github/workflows/
│   └── birthday-check.yml        ← расписание запуска
├── requirements.txt
├── .env.example
└── README.md
```

## Шаг 1. Создать репозиторий на GitHub

1. Создайте новый репозиторий (можно приватный — он будет содержать email-адреса
   сотрудников).
2. Загрузите в него все файлы из этого архива, сохранив структуру папок.

## Шаг 2. Подготовить общий файл со списком

1. Откройте `data/employees_template.xlsx`, замените демо-строки на реальных
   сотрудников.
2. Сохраните файл под именем **`data/employees.xlsx`** (именно так, без
   `_template`) и загрузите в репозиторий.
3. Обязательные колонки: **ФИО**, **Дата рождения**, **Email**. Остальные —
   на ваше усмотрение.
4. В дальнейшем, чтобы обновить список (новый сотрудник, новая дата, новый
   email), просто отредактируйте этот файл в репозитории — рассылка сама
   подхватит изменения при следующем запуске.

## Шаг 3. Настроить почту (SMTP)

Нужен почтовый ящик, от имени которого будут уходить письма. Проще всего —
Gmail с «паролем приложения» (App Password), но подойдёт любой SMTP.

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**,
добавьте:

| Имя secret | Значение (пример для Gmail) |
|---|---|
| `SMTP_SERVER` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` |
| `SMTP_USERNAME` | `you@gmail.com` |
| `SMTP_PASSWORD` | пароль приложения (не обычный пароль от почты) |

Необязательные настройки — там же, но во вкладке **Variables**:

| Имя variable | Назначение | По умолчанию |
|---|---|---|
| `SENDER_NAME` | Подпись в письме | `Коллектив компании` |
| `MILESTONE_START` | С какого возраста считать юбилеем | `50` |
| `MILESTONE_STEP` | Шаг юбилеев (каждые N лет) | `5` |
| `REMINDER_DAYS_BEFORE` | За сколько дней до даты слать письмо (0 = в сам день) | `0` |

## Шаг 4. Проверить расписание

По умолчанию скрипт запускается каждый день в 07:00 по Алматы
(`.github/workflows/birthday-check.yml`, строка `cron: '0 1 * * *'`).
Чтобы поменять время — отредактируйте cron-выражение (время указывается в UTC).

Запустить вручную (для проверки, не дожидаясь расписания):
вкладка **Actions → Birthday Jubilee Check → Run workflow**.

## Сайт проекта

В папке `docs/` — две страницы:

- **`index.html`** — оформленное описание того, как всё работает.
- **`analytics.html`** — аналитика: выбираете любую дату и видите, сколько
  юбиляров приходится на этот день, сколько поздравлений уже отправлено к
  этому моменту (по `data/sent_log.csv`) и полный список юбиляров года с
  разбивкой по подразделениям. Страница читает `data/employees.xlsx` и
  `data/sent_log.csv` прямо из репозитория — правите список, и цифры на
  странице сразу обновляются при следующем открытии.

Чтобы сайт открылся по ссылке `https://ваш-логин.github.io/название-репозитория/`:
**Settings → Pages → Source: Deploy from a branch → Branch: `main` / папка `/docs`**.

> Аналитика работает только через веб-сервер (GitHub Pages и подобные) —
> при открытии `analytics.html` напрямую двойным щелчком с диска браузер
> блокирует чтение файлов данных.

## Как определяется юбилей

Возраст, который сотрудник получает **в этом году** (по году рождения), должен
быть ≥ `MILESTONE_START` и кратен `MILESTONE_STEP`. То есть при настройках
по умолчанию — это 50, 55, 60, 65, 70 лет и так далее, в день рождения.

## Как определяется обращение «Уважаемый» / «Уважаемая»

По окончанию ФИО: `-ович`, `-евич`, `-улы/-ұлы` → «Уважаемый»;
`-овна`, `-евна`, `-кызы/-қызы` → «Уважаемая». Если окончание нестандартное —
подставляется нейтральное «Уважаемый(ая)» (стоит проверить такие строки
вручную).

## Локальный тест (необязательно)

```bash
pip install -r requirements.txt
cp .env.example .env   # заполните реальными SMTP-данными
export $(cat .env | xargs)
python scripts/send_congrats.py
```

## Важно

- Файл `data/employees.xlsx` содержит личные данные (email, даты рождения) —
  держите репозиторий **приватным**.
- `data/sent_log.csv` коммитится обратно в репозиторий автоматически —
  не удаляйте и не редактируйте его вручную, иначе возможны повторные письма.
- Для Gmail обычный пароль от аккаунта не сработает — нужен именно
  [App Password](https://support.google.com/accounts/answer/185833).
